## 1. 프로젝트가 무엇인가

**DPE는 SK스퀘어(KOSPI 402340) 주가가 전일 대비 왜 움직였는지 답하는 IR 매니저용
챗봇입니다.** 챗봇 자체는 이미 CLI(`main.py`)로 돌아갑니다. 지금 하는 일은 챗봇 개발이
아니라 **그 뒤에 있는 설명 엔진의 고도화와 검증**입니다.

설명 대상은 2단 구조입니다.

```
skq_ret (실제 수익률)
  − nav_implied_ret (NAV 기반 기대수익률)
  = divergence           ← 1차 잔차. 모델의 타깃
  − 팩터모델 예측
  = 모델 잔차            ← 2차 잔차. 뉴스가 설명하려던 대상
```

SK스퀘어는 SK하이닉스 지분이 NAV의 대부분이라, IR이 받는 질문은 "얼마나 움직였나"가
아니라 **"하이닉스 때문인가, 우리 때문인가"**입니다. divergence가 그 "우리 때문"에
해당합니다.

**Phase 1 결론 (확정)**
- 숫자 팩터는 divergence를 설명한다 — 확장윈도우 OOS R² 0.2357, 부호정확도 0.7259 (OOS 704일)
- 그 설명력은 사실상 **F3 수급**이 만들고 **F5 선물**이 보조한다
- **뉴스는 방향도 크기도 설명하지 못했다** — 뉴스 단독 OOS R² −0.0310, 부호정확도 0.5038,
  판별 ROC-AUC 0.5013. 가장 안정적인 뉴스 피처가 `news_availability_partial_text`
  (기사 본문 확보 여부를 나타내는 **수집 상태 플래그**)였다. 모델은 뉴스 내용이 아니라
  뉴스를 어떻게 수집했는지를 학습했다
- 딥러닝(2층 MLP)은 트리 계열을 이기지 못했다 — 국면 전환 구간에서 R² −22.8로 발산

**탐색 실험 결과 하나** — `output/review_20260918/baseline_reproduction.json`
F3+F5 14개 피처만 쓴 축소 모델: R² 0.1721 / MAE 1.7008 / 부호 69.18%
(전체 30개는 0.2357 / 1.6060 / 72.59%). 즉 **"개별 제거에서 유의하지 않은 카테고리는

## 8. 지켜야 할 규약

- **두 뉴스 JSONL은 append-only.** 수정이 필요하면 새 레코드를 추가하고 큐에
  `superseded`로 남깁니다. 스키마 검증 통과분만 붙입니다
- **라벨은 기사 본문만 보고 정합니다.** 주가·divergence·고잔차 여부를 보고
  `sentiment_score`·`ex_ante_impact_direction`을 채우면 검정이 무의미해집니다
- **`event_name`·`sampling_role`은 모델 입력 금지.** 누설 차단 7개
  (`divergence`, `divergence_ma5`, `nav_discount_pct`, `nav_discount_delta`,
  `nav_discount_vs_ma20`, `nav_discount_z60`, `skq_vol20`)도 예외 없이 제외
- **`tools/build_event_residual.py` 재실행 금지** — Sean의 수기 큐레이션을 덮어씁니다
- **챗봇 금지 규칙 3개** (아직 코드에 미적용): 뉴스 기반 방향 서술 금지 /
  뉴스 개수·감성 점수 인용 금지 / 발생 확률 절대값 보고 금지
- **모델 기여도와 인과를 구분해 서술합니다.** "모델상 수급 변수의 기여가 컸다"와
  "수급이 원인임이 입증됐다"는 다릅니다
- 원본 데이터·모델·프롬프트를 바꿀 때는 **먼저 Sean에게 확인**하십시오
